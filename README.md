## 🚀 Featured work

### 🗳️ ALX Polly &nbsp;·&nbsp; [Code](https://github.com/BrianBett125/Polling-App) &nbsp;·&nbsp; [Live app](https://polling-app-green.vercel.app)
**Polls with link and QR sharing, built with AI-assisted engineering and verified by tests.** Signed-in users create and manage polls, and anyone with the link can vote and see results. Voting runs through a Postgres function only the service role can execute, with server-issued, HMAC-signed voter cookies, Row Level Security, database-backed rate limits, Cloudflare Turnstile and strict security headers. Every poll gets a QR code (PNG or SVG), a generated social preview card, CSV export, closing times and light and dark themes. Tested against real Postgres, with CI and an axe-checked accessible UI. The README documents exactly where the one-vote-per-browser rule can be beaten.
<br/>`Next.js 15` `React 19` `TypeScript` `Tailwind 4` `Supabase` `Vitest`

## 🤖 AI-assisted engineering

I use AI across the whole lifecycle, and I treat it as a force multiplier, never a substitute for judgment. The rule I work by: **AI-written code gets reviewed and run, never trusted.**

| Stage | How AI helps | What keeps it honest |
|:--|:--|:--|
| **Planning** | Sketching data models and trade-offs | I make the design call and write down why |
| **Building** | Drafting server actions, database functions and UI | Code review, then running it |
| **Testing** | Writing unit and real-Postgres test suites | Every bug fix ships with a regression test |
| **Debugging** | Tracing failures and bad migrations | Reproduce first, fix second, test third |
| **Shipping** | CI, deploy scripts and smoke checks | Post-deploy checks against the live app |

## 🧠 How I work

- **Readable first.** Code is read far more than it is written.
- **Tested.** Untested code is a bug you haven't found yet.
- **Ship early, learn fast,** then improve with evidence.
- **Own the lifecycle.** Design, build, deploy, support.
- **Honest about limits.** I document where a system breaks, not just where it shines.

> Understand the problem → design the system → build it → ship it → learn → improve.
